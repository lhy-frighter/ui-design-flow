# 艺术方向与视觉工艺

在提出设计方向前读 1–3 节；实现和打磨时按需读 4–8 节。目标是产品特定的表达与成熟工艺，不把「高级」固定成深色、衬线、低对比度、大留白或微动效。

## 1. 从内容推导方向

先写三句话：用户来做什么；产品最有区别的事实/内容是什么；完成任务时应该感到什么。再写一句反例：如果把 logo 和文案换成其他行业，这个构图还完全适用吗？若是，检查是否只套了模板。

构想可以来自行业真实的排版传统、材料、空间、数据表达或内容本身；提取可复用的节奏和关系，而不是把界面装扮成某件工具。不要只在「流行默认风格」和它的反面之间摆动。

页面按用户成功方式区分：

| 场景 | 设计的主要工作 | 表达可落在哪里 |
|---|---|---|
| 营销/决策 | 建立理解与可信度，促成明确下一步 | 内容叙事、主图、排版、真实证据 |
| 日常操作 | 快速比较、选择、执行与恢复 | 信息密度、数值层级、状态色、对齐与反馈 |
| 阅读/理解 | 持续阅读与定位 | 文字尺度、行长、段落、目录、图文关系 |
| 作品/体验 | 让作品本身被感知和探索 | 作品比例、视序、过渡、界面退让 |

一个产品可含多种场景。工作台不要沿用官网 hero；阅读页不为「冲击力」牺牲段落。工作台无需强迫制造装饰记忆点，精确稳定也可以形成身份。

## 2. 怎样产生真正不同的两个方向

每个方向用一张卡：

```text
名称与概念：从产品真实内容出发的一句话
适用场景：服务哪个用户任务
构图：用户先看哪里、接着看哪里；附简图或 HTML 片段
文字：标题/正文/标签/数字角色，实际字体与回退
颜色与表面：角色色、背景关系、层级表达
主体：真实图像、内容、数据或交互中的哪一个承担识别度
状态：窄窗/长内容/空态时怎样保持
代价：性能、资产、维护、用户习惯
拒绝项：这个方向明确不使用什么
```

保持相同内容、数据、视口和完成度，让差别来自设计决定。不要用精修方案对比草率草图来诱导选择。两个方案中至少一个关键结构不同：例如围绕「今日待处理队列」还是「按对象分组的空间」，而非换主题色。

已定品牌内扩展页面，只探索结构；局部打磨只提出针对性调整。用户已明确的方向无需再做方案竞赛。

## 3. 方向约定与代表页

选定后，在 DESIGN.md 写明：核心概念、适用页面、用户否定项、信息顺序、版式参数、字体角色、语义色、材质、动效用途、成本和例外。

先实现包含真实内容、主动作、一个高频组件与一个边界状态的代表页。看过它再铺全站，便于在低成本时发现比例和密度错误。设计描述不能替代实际画面。

## 4. 排版：成熟感首先来自内容关系

- 用角色建立尺度：大标题、区块标题、正文、标签、辅助信息、数据。不必统一限定五档，也不为每处新建字号。
- 先用字重、留白与位置区分层级，再决定是否需要字号差。小到读不清、淡到看不清不能当精致。
- 一套调好的字体足以支撑很多操作页。增加第二套要有明确角色；已有品牌字体继续沿用。选择系统字体也需说明设备与语言适配理由，不为独特而增加无关字体。
- 普通 Web 正文可从 16px 附近起，紧凑应用按实际场景调节；保留缩放。英文长文可从约 45–75ch 起；中文以实际汉字行长检查，不能把 ch 当汉字数量。
- 中文正文行高可从 1.6–1.85 起试，标签、按钮和密集表格单独调；数字比较用 tabular-nums，单位与小数精度一致。
- 标题换行按短语和阅读顺序检查；text-wrap: balance/pretty 作为渐进增强。不为一个视口写死换行后忽略窄窗。
- 中英文混排、标点避头尾、超长链接、缺字/字重回退、200% 缩放要实测。采用 line-break/text-autospace 等能力前核对目标浏览器支持。
- 检查字体加载前后布局变化；只加载用到的字重。离线 Electron 优先自带可分发字体或可靠系统栈；Web 按项目隐私、性能和资产策略决定。

## 5. 构图、比例与空间

- 把信息组织成组，再给组之间留空间。组内距离小于组间距离，工具与它作用的内容靠近。
- 确定主轴、内容宽度和对齐线；同族组件重复位置一致。光学修正以真实画面为准，不能靠数值相同推断看起来齐。
- 留白承载节奏与聚焦；高密度承载比较效率。不要为了铺满半屏编造内容，也不要用巨型空白掩盖缺少组织。
- 卡片用于可独立理解、比较或操作的对象。表格、列表、行内分隔和版面本身可以承担结构，避免容器层层嵌套。
- 首屏表达主任务；长页要有节奏变化与阅读锚点，不能每节都是等宽三卡。变化来自内容结构，不靠随机不对称。
- 窄屏重新分配信息优先级与操作位置，保留核心任务；桌面专用界面验证最小窗口，不盲套移动布局。

## 6. 色彩、材质与图像

先定义角色：canvas、surface、elevated、text、text-muted、border、action、positive、warning、danger、focus。各主题独立校验，不只是反转色值。语义色不能随页面装饰改变意义。

表面层级以明度关系、分隔或投影建立一致规则。阴影需有合理方向与扩散；边框加阴影可以合理存在，但不能给每个容器无差别叠加。玻璃只在确需透出背景和空间关系时使用，并验证滚动背景上的可读性及无模糊回退。

高级感不来自固定配方。黑金、米白衬线、酸绿暗底、报纸网格、柔和渐变都可能适用，也都可能只是默认模板。判断依据是产品和所选方向，而非禁用某个颜色或字库。

图像先确定角色：解释、证明、表达气质还是展示作品。控制裁切焦点、光线、色调、背景和比例；一张有意义的图优于无关图库拼贴。使用真实产品截图时必须来自实际产品；概念图与演示数据明确标注。没有合适素材时让排版或内容承担主体，不拿随机程序纹理冒充设计。

## 7. 动效与细节

先写「触发 → 用户需要理解的变化 → 动效反馈 → 打断/结束/降级」。界面应在不等待动画时也可操作。

- 约 120–220ms 的控件反馈、180–320ms 的面板过渡可作为起点，实际按距离和场景调；不是全局硬值。
- 进入与退出、展开与折叠、加载与完成应有清晰连续性；快速反复操作时不排队、不闪退。
- 非交互自动动效集中于有意义的主体，不给每张卡片套同一入场。减少动效时保留即时反馈与状态，不必把所有 transition 一刀切归零。
- 避免动效触发布局抖动；滤镜、模糊和 WebGL 看真实设备成本。重任务、隐藏窗口和失败状态需降级或暂停。
- 统一图标描边、视觉尺寸和基线。检查 focus/selection/caret、链接下划线、滚动区、数字单位、按钮 loading 后宽度等细节；保留平台已有可用行为。

## 8. 交付前的审美复核

先独立看画面，再对照方向约定：

1. 主体、次序和首要动作能被快速理解吗？操作页先看真实任务；不要强迫所有画面都有唯一巨大 CTA。
2. 文字角色是否一眼可辨？最长真实文案是否仍成立？
3. 同样 logo 换成其他产品后，哪些地方仍能证明这是当前产品？如果完全没有，重新检查方向而不是再加一层装饰。
4. 材质、图像、字体和动效是否来自同一设计逻辑？去掉任一装饰会更清楚吗？
5. 代表页和其他页是否共享规则，但保留内容需要的布局差异？
6. 弱状态、空态与窄窗是否也有完成度，而非只有首屏成功态精修？

用 `位置 → 可见问题 → 对用户/方向的影响 → 最小有效改法 → 复核证据` 给意见。不要用模糊的「不够高级」或没有证据的总分决定是否交付。
