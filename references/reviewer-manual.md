# Design Flow 视觉与交互评审手册

适用于主 agent 自查或被委派的评审 agent。评审任务只给可执行意见，不自行修改项目；主 agent 按授权修复。只有被要求实现时才改代码。

## 输入与能力

先确认本次范围、页面/路由、视口、主题、关键状态、DESIGN.md「访谈定案」与方向约定、可用截图/运行地址。输入不全时先查项目与现有产物；真正缺少的关键信息再问，不虚构用户决定。

DSH 可使用 read_image / oil_ui_shoot；其他环境使用实际提供的图片、浏览器或自动化工具。需要 480px/180px 缩略图时，把原视口截图等比缩小，不能改成窄视口重排后冒充缩略图。

有委派能力且宿主允许时可独立复查；否则由同一 agent 先做视觉判断再做机械检查，并注明实际检查方式。不要声称自查等于独立评审。多个评审者不要同时操作同一个桌面窗口。

## 第一遍：整体设计判断（先于扫描结果）

| 维度 | 检查问题 | 证据 |
|---|---|---|
| 任务与内容 | 主要任务是否清楚？信息顺序是否支持下一步？ | 引用当前标题/字段/动作与所在区域 |
| 方向特定性 | 构图、图像与语言是否属于当前产品？是否偏离已选方向？ | 对照方向约定具体条目，区分主观偏好 |
| 视觉层级 | 第一视线落点是否有用？次级信息是否仍可读？ | 截图区域、文字角色与实际值 |
| 构图与节奏 | 内容组、对齐线、宽度和留白是否有关系？是否容器过多？ | 指出组间/组内关系和受影响对象 |
| 排版 | 角色、字重、换行和语言混排是否稳定？ | 长标题、正文、数值的代表例子 |
| 色彩与材质 | 色彩是否承担语义？阴影/边框/玻璃是否一致？ | 主题、背景、具体组件状态 |
| 资产与表达 | 图像是否相关且裁切合理？是否存在假截图、假证言？ | 资产来源与当前内容；未知则标待核实 |
| 工艺 | 图标、基线、圆角、反馈是否统一？ | 同族组件对比，不把像素相等当光学一致 |

保留已经有效的设计。区分「功能或规范问题」「偏离已确认方向」「可选表达建议」；不要用个人偏好推翻用户决定。工作台的成熟感可以来自精度，无需强行添加装饰焦点。

## 第二遍：任务流与技术质量

1. **核心路径**：实际执行进入 → 操作 → 结果 → 恢复/回退；验证按钮有效，提交不是假成功。
2. **适用状态**：loading/empty/error/success/disabled、长内容与大量数据；权限/离线按产品范围检查。失败保留输入且可恢复。
3. **布局边界**：Web 检查目标桌面和窄屏，桌面专用应用检查正常/最小窗口；横向溢出与受控表格滚动区分。验证缩放和长语言，不能只测首屏。
4. **键盘与语义**：Tab 顺序、可见且不被遮挡的 focus、弹层进出焦点、Escape/返回与控件标签。原生语义优先，禁止无意义地加 ARIA。
5. **目标尺寸**：触屏常用操作尽量达到 44×44 CSS px 的产品目标；WCAG 2.2 AA 的 24×24 要求含间距、行内等例外，不能把旧的统一 32px 阈值当合规结论。密集控件逐个判断，图标尺寸不等于热区。
6. **对比度**：普通文字至少 4.5:1，大文字至少 3:1（约 24 CSS px，或约 18.67px 粗体）；关键非文本控件按适用规范检查。渐变、图像、透明叠层应测实际背景；DOM 近似采样只作线索，不能直接宣布合规。
7. **动效**：反馈连贯且可打断；内容默认可见；reduced-motion 有合适替代；无鼠标悬停也能完成核心任务。
8. **运行质量**：本次相关控制台错误、断图、死链接、重复请求、布局抖动和字体回退。把扩展/环境噪声与项目错误分开。
9. **多语言**（适用时）：新增键在目标 locale 齐全；不绕过现有 i18n；长语言与中英文混排可用；语言切换保留合理上下文。

## 营销/注册/付费页的额外检查

- 标题能否让目标访客理解产品和下一步？引用当前文本，不按模板改写事实。
- 主动作是否清楚、与点击后的行为一致？不要用同权按钮争抢注意力。
- 表单每个字段是否为当前目的必需？减少无依据的字段与阻塞；不把固定字段数或臆测流失百分比当规律。
- 价格、限制、证言与客户信息是否真实清晰？没有证据不添加承诺。
- 操作完成后的下一步是否明确？性能、OG/canonical 等仅按当前项目与任务检查。

内部工具跳过转化审查。没有用户研究或实测数据时，改善效果只标假设，不承诺提升比例。

## 截图与测量的证据边界

截图记录时间/版本、视口、路由、主题和数据状态。像素 diff 仅在相同条件下判断变化；重设计的预期变化不应追求 diff 归零。

只有像素分析时，可报告图片尺寸、指定区域的颜色分布与两图差异框。不能根据边缘白色或深色横条确定 DOM 元素、遮挡原因或标题栏高度。需要用 DOM bounding box、computed style、截图对应位置或真实操作交叉验证。

未看图则标「未完成视觉验收」，未运行则标「静态检查」。自动审计无报错只说明已覆盖规则，没有证明审美成立。

## 输出与修复优先级

先给任务范围和实测覆盖，再给 2–3 处值得保留的设计与按影响排序的发现：

```text
[P1/P2/P3] 路由/区域/选择器
现象：可见事实，附截图或文件/行号
影响：阻塞哪个任务，或违背哪条已确定方向
建议：最小有效修改及预期结果
复核：需要操作/截图/测量什么
性质：事实 / 推断待验 / 可选建议
```

P1：关键任务阻塞、数据/操作结果误导、严重不可用；P2：显著层级/布局/可访问性问题或方向偏离；P3：不阻塞的工艺改进。不要为了凑数制造问题，不用平均分掩盖阻塞项。

主 agent 逐项标「已修且复核 / 有理由保留 / 待验及影响」。相关问题解决并达到本次交付范围后结束，不因个人审美无限迭代。

## 技术路由复核（适用时）

- 关键技术能否对应访谈原话/决定？是否沿用了已有可行方案？是否把视频冒充实时交互？
- 同一属性是否有多个动画驱动者？快速切换/返回后，监听、timeline、观察器、渲染循环与 GPU 资源是否清理？
- 网页查真实交互和中间状态，视频查关键帧/seek/音频与导出；截图不能证明帧率，HTML 预览不能证明成片正确。
- WebGL/context、媒体加载、减少动效、键盘/触屏退路是否保持核心任务？缺服务/缺工具的项目是否标待验？
- Hallmark 适配是否保留用户已定气质、自有设计想法和项目规范？不能为通过偏好检查改掉任务要求。

只检查当前实际选中的分支；未引入的视频/图形技术不扩展审计。新状态影响判断时复核相关片段，不无限重做整个产品。

## 资产和扩展技术复核（按实际选型）

- 资产“已可用/待制作/占位/缺失”是否真实？优化是否保留原始文件、许可/署名、模型节点和拾取映射？
- 原生转场失败时业务更新是否仍且只执行一次？原生滚动能力缺失时内容是否仍可读？
- Rive 状态与业务状态是否解耦，画布是否有 DOM 等价？图表是否明确来源、单位、空态、异常值和非 hover 数据获取方式？
- 压缩的模型是否附带所需解码依赖，并在目标离线/在线条件实测？不能只凭字节减少宣布性能提升。
- 性能记录是否给设备、环境、步骤、采样方法与限制？截图、rAF 间隔、录屏不能自动证明 GPU 帧率或所有设备表现。

细节与记录模板见 [asset-and-performance.md](asset-and-performance.md)。未选中的技术跳过。
