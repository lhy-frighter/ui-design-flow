# 资产、复杂度与运行证据

在确定依赖资产的技术前读 1；复杂动效/图形读 2–4；简单局部调整只做相关检查。不要求每个项目引入新工具或创建一堆空文件。

## 1. 资产可得性检查

检查结果与技术决定放在已有 DESIGN.md 或资产清单中：

```text
资产 ID / 用途 / 使用的效果 ID：
文件或已核验来源：
状态：已可用 / 可制作且有人负责 / 占位 / 缺失
类型、尺寸/时长、体积及可编辑源：
授权/署名要求、是否允许分发或修改：
工具链：runtime、renderer、解码器/WASM/字体/外链依赖：
交互契约：Rive 状态输入、模型节点/拾取对象、视频时间等：
负责人/下一步与缺失时的替代：
```

缺失资产会改变选型：没有 .riv 就不能把 Rive 路由标为已实现；没有可导出的 Spline 场景不承诺完全本地运行；没有字体授权不直接把字体打包。只记录与本次实际资产有关的信息，不凭项目名字推断许可。

允许 agent 在既有授权内用程序几何、DOM/SVG 或明确占位先验证交互。占位是未完成资产，不是已交付的真实照片、模型或数据。

## 2. 效果复杂度和成本

| 层级 | 常见内容 | 实施方式 |
|---|---|---|
| 轻量 | 单控件、短转场、静态图文 | 沿用当前技术，局部实现并复核 |
| 协调 | 多组件、手势、滚动、状态机、图表联动 | 记录状态与驱动所有权，验证快速中断/异常数据/资产失败 |
| 高不确定性 | 实时三维/自定义 GPU、密集粒子、大资产、外部生成服务 | 先跑风险最高的小样，达到目标再扩展；失败简化或降级 |

层级是风险分类，不是固定评分。每个效果写一句用户收益，评估依赖下载、首屏影响、渲染成本、资产制作、维护和服务费用；已知数字写依据，未知数字标目标/待测。没有可观察收益的装饰可删减，不因选了库就必须增加效果。

性能预算按目标环境协商/推导：例如开始反馈的延迟、交互可用时间、加载字节与峰值对象数。不要给所有项目套同一个帧率或把目标写成已测结果。

## 3. 三维资产生产与优化

资产已采用 glTF/GLB 且体积或渲染成本影响目标时，按需评估 [glTF Transform](https://gltf-transform.dev/cli)。它是资产处理工具，不是新的动画引擎。

- 保存原始资产并输出独立优化副本；先查实际版本 CLI/help，选适合的去重、纹理缩放、压缩或网格处理，不盲跑一串破坏性变换。
- Draco/Meshopt/KTX2 等方案依项目加载器、解码器/转码器支持选择；压缩后的文件可能需要额外运行依赖，离线部署必须一起考虑。
- 优化前后核对尺寸/朝向、材质、透明、动画、骨骼、节点名及 raycast 目标；裁剪/合并对象可能破坏点击工序的业务映射。
- 同时比较加载体积、解码时间、首次可交互与实际渲染；文件变小不保证每项性能都提升。
- 程序化咖啡处理站没有模型文件时，先优化几何复用、draw calls、阴影、纹理尺寸和 DPR，不强行加 glTF 工具链。

## 4. 真实验证记录

```markdown
### PERF/FX-编号
- 当前代码/版本、效果与页面：
- 设备、系统、浏览器/版本、视口、DPR：
- 构建模式、冷/热缓存、网络条件、测试数据规模：
- 操作步骤与观测时段：
- 使用工具/采样方式、截图/录屏/trace 路径：
- 起止/中间/快速反复/返回重入结果：
- 测量结果及其范围；目标是否达到：
- reduced-motion、触屏/键盘、无 GPU/断网/资产失败结果：
- 优化前后可比较条件、未验项与影响：
```

以实际提供的 DevTools、浏览器自动化或项目测试为准。rAF 间隔只能说明所采样回调节奏，不能独自证明 GPU 帧率或所有设备流畅；短录屏和平均 FPS 也可能漏掉卡顿。需要时看帧时间分布、长任务与加载过程，说明采样限制。

截图验证画面，操作记录验证行为，性能 trace 验证测量范围。三类证据不能互相冒充。没有实测环境时保留验证步骤和未验项，不自动安装系统级分析工具或声明通过。

## 5. 交付收口

关键状态已验证、资产/依赖去向清楚、目标未达项有退路或明确影响时交付。重度效果只有录屏而没有可操作产物时，不能作为网页实现完成。仅改 skill 指令不等于已跑过这些技术；报告明确区分格式/构建检查与真实场景测试。
