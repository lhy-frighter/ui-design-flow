# 深度设计访谈题库

本表用于寻找遗漏，不是逐项问卷。优先选会改变方案的未知项；已知项填依据，不适用项跳过。沿「目的 → 任务 → 范围 → 结构 → 表达 → 验证」推进。

## 1. 目标与用户：为什么值得改

| 决策 | 首问示例 | 有意义的追问 / 可观察产出 |
|---|---|---|
| 改版动机 | 最近哪一次使用让你觉得必须改？ | 看不懂、找不到、操作慢、缺信任，还是视觉不符合身份？请指页面或场景 |
| 成功结果 | 做完后最希望用户更容易完成哪件事？ | 从入口到结果的具体任务；没有数据时不承诺效率或转化百分比 |
| 主要用户 | 第一版首先服务哪一类人？ | 新手/熟练者、个人/协作、使用频率；别把所有人都当同一用户 |
| 使用环境 | 这个任务通常在什么设备和情境发生？ | 鼠标键盘、触屏、窗口并排、弱网、长时间使用；尺寸与平台能查则自己查 |
| 优先级 | 「好看」与「方便」发生冲突时，你最不愿牺牲什么？ | 针对当前冲突给具体选项，不能泛泛逼用户二选一 |

深入示例：用户说「我的 Agent 页面太乱」→ 问最常做的是开新任务、回找历史还是盯运行进度 → 若选运行进度，再问最需要先看到阻塞原因、当前产物还是下一步操作。先不问玻璃模糊强度。

## 2. 核心任务：从进入到结果

| 决策 | 首问示例 | 继续深入的条件 |
|---|---|---|
| 入口与首屏 | 用户进来第一眼要判断什么，接着做什么？ | 不同入口产生不同上下文时，区分首次/返回/深链 |
| 主路径 | 以一条真实记录为例，从开始到完成经过哪些决定？ | 找重复、回退、阻塞点；让代码验证已有步骤 |
| 信息优先级 | 哪三项信息会改变用户下一步动作？ | 把重要但不紧急的元数据移入次级区；不能仅按字段顺序排版 |
| 高频与低频 | 哪些动作每天做，哪些偶尔才用？ | 常用动作近数据；低频工具可收纳但仍可发现 |
| 反馈与恢复 | 操作失败或耗时较长时，用户最担心什么？ | 重试、取消、撤销、恢复输入、进度可信度；由现有功能约束 |
| 信息密度 | 同屏需要比较多少条/多少列，还是逐条阅读？ | 用代表性内容讨论列表/表格/卡片，避免只问「密一点还是松一点」 |

## 3. 范围与现实约束：改到哪里

- 本次替换视觉身份、沿用品牌重组结构，还是只打磨现有页面？用户已说清时直接继承。
- 如果时间只够做好一条路径，哪条最值得先做？其余是否保留原状？
- 哪些功能、路由、术语、资产、操作习惯不能改变？先查已写的规范，不重复询问。
- 可以改信息架构到什么程度？允许隐藏次要信息是否意味着仍能通过展开/筛选找到它？
- 数据、字体、图片、账号由谁提供？未拿到的资产怎样标注？不能把演示内容当真实证明。
- 有哪些兼容或性能约束会限制方案？框架/依赖自己查；无法从仓库得知的设备目标才问。
- 是否需要安装包或只是代码交付？外部上线/发版只按用户的明确范围执行。

## 4. 体验结构：在视觉之前解决

- 同一个产品内，哪些页面负责操作，哪些负责阅读、说服或沉浸展示？不同页面可以共享 tokens，不能一套 hero 铺全站。
- 导航按对象、任务还是时间组织？以用户最近一次找不到的内容验证它。
- 主次动作是否竞争？何时是就地展开、侧栏、独立页面或模态？根据任务连续性选择，不默认抽屉化。
- 哪些信息必须始终可见？哪些可以折叠？折叠前是否能读到摘要与异常数量？
- 确认、删除和不可逆动作需要怎样的保护？已有授权和产品行为继续沿用。
- loading、empty、error、success、disabled、long-content 哪些适用？大量数据、权限不足、离线和首次使用按业务挑选，不把不存在的状态强加给项目。

## 5. 审美与身份：把「高级」翻译成决定

| 需要确定 | 好问题 | 不要这样问 |
|---|---|---|
| 不满意的根源 | 当前哪一块最廉价：层级太平、排版松散、颜色吵，还是图像与产品无关？ | 想不想高级一点？ |
| 气质与对象 | 想让谁感到「专业」？你希望他第一眼相信什么？ | 要现代/科技/简约哪种？ |
| 参考继承 | 这张图中最想借的是比例、留白、文字还是动效？明确不要哪部分？ | 是否照着它做？ |
| 识别度 | 用户离开后，最希望记住产品哪一项特征？ | 要不要加 WebGL？ |
| 表达强度 | 同样内容，偏稳定工作台还是更有表达的展示？它们对日常操作的代价是什么？ | 高级感强度 1–10？ |
| 材质 | 需要哪些层级关系被用户看懂？用平面、分隔线还是轻投影最清晰？ | 阴影多少 px？ |
| 字体 | 现有字体在哪些内容上读起来别扭？有品牌字或需要覆盖的语言吗？ | 喜欢 Manrope 还是 Inter？ |
| 动效 | 哪个状态变化最需要方向或连续性？ | 要不要每张卡片入场？ |

需要视觉比较时，给相同内容的片段，明确两者的结构差别与代价；不要只提供两种颜色的同一张模板。对数据后台，识别度可以来自数字层级、图表语义、状态标识和密度，不强行做海报。

## 6. 压力测试与验收：避免只有成功截图

只挑会改变当前方案的情境：

- 标题变两倍长、中文与英文切换、数值为 0/负值/极大值时，层级还成立吗？
- 列表从 3 条到 300 条时，比较、筛选与批量处理是否仍可用？
- 窄窗并排、200% 缩放、键盘、触屏、减少动效偏好下，关键任务是否完成？
- 没有推荐图片或字体加载失败时，画面是否仍有清晰结构？
- 演示中的第一步/最后一步是什么？用什么页面、状态与操作记录证明已完成？

结束前把每个高影响目标连到证据：`目标 → 设计决定 → 页面/状态 → 检查方法`。缺证据可列为待验，不得伪报通过。

## 7. 示例：一次有深度的往返

用户：「给学习应用做得高级一些。」

第一问：「这次最值得先改善的是每日开始学习、学习过程，还是回顾进度？我推荐先定每日开始这条路径，因为它决定首页应该围绕任务还是数据。」

用户：「每日开始，但我不想满屏打卡数据。」

接着查现有首页和学习入口，记录「每日开始优先；不把打卡数据作为主视觉」。下一问转为：「进入首页时，你想立刻继续上次内容，还是先选今天练什么？继续上次更快；先选内容更有控制感。」

在路径清楚之后，再比较相同真实内容下的两种排版。记录用户选中的结构与拒绝原因，不把「高级」擅自翻译成深色、金色与大圆角。

## 8. 动效与技术路由的体验问题

- 这次交付网页、视频，还是两者都要？录屏是否要证明真实运行？
- “电影感”具体是镜头运动、景深、材质还是叙事节奏？用户需要随时操作吗？
- 转场中连续点两次/返回/切换对象时，应中断、覆盖还是等待？
- 图形需要随真实数据变化吗？哪些数字、字样和时间必须准确？
- 能拖动旋转观察背面吗？是否需要点击场景中的某个设施？已有决定直接记录。
- 不支持 GPU、减少动效或触屏操作时，哪条核心任务必须保留？
- 外部素材/服务不可用时，可接受海报、真实录屏、简化场景或延后素材制作中的哪种？

问题只问有影响的未知项；不把这些题设为固定必答。把用户答案连到效果 ID，再交给执行 agent 选技术，不要求用户记住库名。

## 9. 资产与复杂度的补问（适用时）

- 已有模型/动画/字体/图片中，哪些能提供源文件、允许修改和分发？能查文件时自己检查。
- 缺少动画或三维资产时，先验证简化交互，还是等待有人制作？只问影响范围的取舍。
- 这个效果为哪一步操作提供价值？用户是否接受换成轻量表达来照顾目标设备？
- 图表要回答什么问题、比较哪些对象，哪些字段是演示数据？不要先让用户投票图表样式。

技术运行依赖、压缩方式与测量方法由 agent 查证；不让用户回答可由文件和官方文档确认的事实。
