# 从 Grill-me 决定到技术实现

适用于交互动效、滚动叙事、二维/三维体验和视频交付；普通静态页面可直接选择现有 HTML/CSS，不强制选库。工具目录见 [motion-catalog.md](motion-catalog.md)，走查实例见 [routing-examples.md](routing-examples.md)。原生转场、状态机、数据和三维专项见 [technology-extensions.md](technology-extensions.md)，资产/复杂度/实测记录见 [asset-and-performance.md](asset-and-performance.md)。

## 1. 路由输入：提取决定，不重复审问

从访谈定案、方向约定、现有代码和参考中提取：

| 输入 | 需要明确的事实/决定 |
|---|---|
| 产物 | 可操作网页、实时场景、成片视频，或网页+视频两份交付 |
| 用户目的 | 每个效果帮助理解、反馈、探索还是叙事；纯装饰是否值得成本 |
| 触发与控制 | 点击/键盘/拖拽/滚动/自动播放；需要取消、倒放、拖动进度、旋转视角吗 |
| 对象与空间 | DOM、路径图形、二维粒子、三维几何/相机、实拍感镜头 |
| 精确度 | 文案和数值是否必须准确、布局是否需随数据更新、是否要求逐帧复现 |
| 环境 | 实际框架、已有动画/渲染库、目标浏览器/设备、离线/网络、可用资产 |
| 预算 | 性能、依赖、制作/维护、服务费用；未知值写待验证，不伪造硬件实测 |
| 退路 | reduced-motion、GPU/网络失败、缺素材/服务、键盘/触屏的等价体验 |

用户只需回答影响体验和范围的决定，技术由 agent 负责。先问“能拖着转看背面，还是固定镜头播放”，不要先问“要 Three.js 还是 Seedance”。已授权技术选型时不再增加同意环节；付费和外部操作依实际授权。

## 2. 先分产物，再分实现复杂度

1. **需要真实交互**：保持页面状态、语义 DOM 和操作路径。简单变化先现有 CSS；跨视图和简单滚动联动先评估 View Transitions / CSS scroll-driven 增强；需要生命周期/控制时用原生 JS/WAAPI；现有框架状态与手势可选 Motion；复杂编排/滚动可选 GSAP。
2. **二维绘图**：少量可访问图形优先 DOM/SVG；大量动态对象再考虑 Canvas 2D。密集粒子/滤镜超出 CPU 预算时做小样评估 WebGL，而非直接升级整站。
3. **真实三维**：React 项目才评估 R3F/Drei；单一 shader 效果可按需评估 OGL。实际需要模型文件时先核实资产与解码依赖，再评估 glTF Transform 优化。需要旋转、光照、遮挡、拾取与相机时考虑 Three.js。WebGL 是底层 GPU API，可作为 Three.js 等方案的渲染基础；只有现成引擎难以满足的定制 shader/渲染管线才直接手写 WebGL。不能把某个 Three.js 版本的渲染后端能力当永久事实。
4. **成片视频**：React 组件化/数据驱动图文视频考虑 Remotion；HTML/CSS/时间轴构图考虑 HyperFrames；生成式镜头素材考虑 Seedance。先核查可用环境、资产和授权，不为做网页自动生成付费视频。
5. **混合需求**：分别产出网页交互方案和视频制作方案；生成的视频可作媒体层，不能替代实时拾取和状态。实际网页的操作证明用真实录屏，不用生成式视频伪造。

6. **多状态图形**：需要角色/插画响应业务状态时评估 Rive，先有资产契约；普通导出动画按素材考虑 Lottie。缺素材时简化或列待制作，不默认整个项目改成画布。
7. **数据表达**：先确认问题与数据契约；普通图表沿用现有组件或 ECharts，特殊数据编码再考虑 D3。图表不因“动起来更好看”就生成虚构数值。

优先复用当前项目已采用且适合任务的方案。只因“更高级”不增库；已有 Motion 满足需求时不额外加 GSAP，反之亦然。Canvas 不等于 WebGL，CSS 3D transform 不等于可自由探索的真实三维场景。

## 3. 选择结果必须可审查

在实现前把简短技术决定合并到 DESIGN.md。不是让用户为每个技术细节投票，而是让其他 agent 能解释并接着做。

```markdown
## 技术路由
### FX-01 效果/场景名称
- 对应访谈决定 ID/原话或出处：
- 用户价值、触发、变化对象、结束状态：
- 产物：实时网页 / 视频 / 混合
- 主方案、沿用的依赖与实现边界：
- 备选方案及未选理由：
- 生命周期：挂载、进入/退出、中断、销毁与资源释放
- 资产状态/负责人/源文件、库版本/兼容/许可与解码依赖：
- 效果复杂度、用户收益、加载/制作/维护成本与预算依据：
- 性能与加载预算（目标及测量环境，未测注明）：
- reduced-motion、无 GPU/无网络、键盘/触屏退路：
- 最小验证片段与成功/放弃条件：
- 实际证据（设备/浏览器/构建/缓存/网络/数据规模与采样方法）、未验项及后续：
```

一个项目可有多个效果，共享方案可合并。框架已确定时不因路由重写框架。对同一元素属性只设一个驱动者；例如 GSAP 控制相机，OrbitControls 在过渡中禁用或协调，不能同时争写相机位置。

## 4. 复杂效果先做最小片段

用一个真实交互/镜头验证最不确定的条件：触摸旋转、字体/字幕、长文字、GPU 压力、快速反复点击、离线加载。成功再扩展；失败按记录降级。不要在四个库上各造一版全站。

版本/API、平台支持、模型能力和许可在实际引入时读官方文档与锁文件；避免写死 latest、古老 UMD、固定 CDN 路径或模型 ID。本文件只是路由，不保证环境装有这些工具。缺少工具时交付可执行的替代或明确待验项，不能报虚假成功。

## 5. 验收按产物分流

- **网页**：实际操作、起止和中间状态、快速中断、卸载再进入、缩放/窄窗、键盘、触屏（目标包含时）、reduced-motion。查看重排/长任务/帧时间并记录设备，不能用截图证明流畅。
- **Canvas/WebGL/Three.js**：自适应尺寸和 DPR 上限、隐藏页暂停、资源释放、context loss/初始化失败、纹理加载、拾取与遮挡。信息与入口提供 DOM 等价；静态海报加可操作工序列表可作为三维退路。
- **Remotion/HyperFrames**：帧率/时长/画幅、确定的时间轴、seek 后与连续播放一致、关键帧/转场/字幕/音频、导出可播放。随机值/当前时间必须受控；不以普通网页预览代替成片验收。
- **Seedance**：先做可用性、费用与资产核查，再生成少量样片；检查主体连续性、动作、画面事实、字样和音频。准确 UI、数字和字幕后期叠加，合成镜头标明其用途，不用来证明产品真实运行。

仅网页动效验收不要求制作视频；只有视频任务才加载对应专用技能。读 [reviewer-manual.md](reviewer-manual.md) 的技术路由复核项后交付。
