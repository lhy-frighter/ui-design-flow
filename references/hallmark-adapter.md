# Hallmark 设计适配层

研究基准：2026-11-01 的 Nutlope/hallmark v2.0.0 入口、microinteractions 与 gates；MIT。原始文件链接见 [sources.md](sources.md)。此分册为本流程重新编写的适配规则，不是完整 Hallmark 安装，也不捆绑其主题库、图片库与 sloplint。

## 何时参与

- 新页面或用户明确要求替换视觉身份：在参考工程后、技术选型前，借其内容驱动构图和设计自审方法。
- 延展、局部 polish：继承项目已有规则，只检查本次涉及的问题；不重新抽主题或改全站。
- 只审查：给有证据的发现，不改代码。只有明确要求重设计时才更换身份。
- 用户点名完整 Hallmark 且环境已安装：先确认实际版本与资源完整性，再按需读取。没有安装则用本适配层，不声称执行了它的 CLI。

## 进入方向选择之前

先把材料分为真实可用、演示占位、缺失三组，明确主任务与第一视线的对象，再决定信息结构。图片、数据、证言与品牌资产不能由审美需要捏造。

为候选方向列出构图、字体角色、色彩关系、表面与交互节奏。相同内容的方向应该有实质结构差别；已锁定方向继续沿用。比较的是本产品适配程度，不是随机求异。

每个已选方向留下简短记录：采用依据、拒绝的默认套路、用户自己的设计想法，以及例外为什么合理。存 DESIGN.md 即可，不强制给 CSS 加第三方标识，也不伪称由 Hallmark 生成。

## 自审的三个层级

| 层级 | 本流程处理 | 例子 |
|---|---|---|
| 正确性与可用性 | 本次交付必查；未满足就修复或明确未完成 | 事实真实性、键盘焦点、适用对比度、关键任务、减少动效路径 |
| 模板化习惯 | 根据任务与已确认方向判断，可保留有理由的选择 | 同尺寸卡片堆叠、无意义编号、无关装饰、标题与信息层级雷同 |
| 工艺 | 按影响打磨，不无限阻塞交付 | 光学对齐、退出节奏、图标基线、复杂主题的细微材质 |

先独立查看页面，找出最弱的一项：内容依据、信息层级、实现完整度、产品特定性、装饰克制或结构重复。以真实观察写一项修复和复核证据，不虚构分数和缺点。

## 微交互如何转入技术路由

从状态而非动效库出发：触发 → 变化对象 → 结束状态 → 中断/退出 → 失败恢复 → 减少动效。将它交给 [technology-routing.md](technology-routing.md)。反馈在内容本身已可见时避免再叠提示；异步操作只有具备可逆机制时才采用乐观更新。对不可逆动作不机械删除确认。

## 明确不直接继承的规则

不引入随机主题抽取、强制换字体、每屏固定字数、全局 overflow 裁切、每次都换宏结构或绝对禁止某种标签/颜色。它们可能与中文密集界面、用户品牌或真实滚动区域冲突。CSS 尺寸动画是否可用应看布局成本与语义，不能以全局禁令代替测量。

本流程的优先级是用户已确认目标、项目规范、可用性和本次范围。第三方规则是证据与方法，不额外授予安装、付费、联网发布或委派权限。
